## TL;DR

O ARCZ **não é um shell vazio** — tem uma base geodesia/geográfica sólida e o
**esqueleto de um editor de cena já implementado e testado**, mas o esqueleto
está **desplugado do renderer**. O `cena.rs` tem um `Editor` completo com picking,
gizmo com 3 modos, e varredura de biblioteca — tudo com testes verdes — mas o
header do arquivo diz explicitamente: *"ainda não está ligado ao pipeline de
GPU — hoje `Recursos` desenha um modelo único"*.

A frase do prompt mestre "o gizmo só funciona pro edifício" é mais grave do que
parece: **não funciona pra nada, porque nunca foi conectado ao mouse**. O Lucas
testou, viu o gizmo visualmente (porque o pipeline de render é persistente e
sobrescreve as linhas do gizmo a cada frame), mas a interação W/E/R/Q/Delete/etc.
**não existe**.

O `server.rs` (preview ao vivo HTTP) e o `renderer.rs` (PNG offscreen) também
só manipulam UM modelo. A cena-multi-objeto nunca foi entregue.

## 4. Plano de ataque — Fase 2 (Núcleo do editor)

Vertical, em 6 fatias pequenas. Cada uma fecha com: testes verdes, build
verde, screenshot/vídeo curto do que mudou, e commit separado.

### E.1 — Plugar `Editor` no `Renderer` (fundação)
**O que:** trocar `Recursos::modelo: Option<MalhaGpu>` por `Recursos::objetos:
Vec<MalhaGpu>` (um por objeto visível). Cada frame: chamar `Editor::adicionar`
para popular a partir do `Config::biblioteca` (novo flag CLI), e
`Objeto::transformar` para subir os vertex buffers. O `Recursos` ganha
`atualizar_objetos(&mut self, &Editor)`.
**Teste de aceite:** `--biblioteca ./biblioteca` carrega 5+ `.glb` e mostra
todos no viewport. O PNG offscreen mostra os 5.
**Risco:** baixo. O `cena.rs` já tem a API.

### E.2 — Picking por clique no viewport
**O que:** no `viewport.rs::window_event`, em vez de tratar o `MouseInput::Left`
só como início de drag, fazer: se não houve drag (soltou no mesmo lugar em
<200 ms), construir raio via `Renderer::raio_no_plano` (que já existe em
`renderer.rs:243`), chamar `Editor::picar(origem, direção)`, atualizar
`Editor::selecionado`. Highlight = mudar o `gizmo` para a caixa do objeto
selecionado.
**Atalhos já existentes:** `R` (reframe) reaproveita.
**Novos:** `F` (focar selecionado), `Delete` (remover), `H` (ocultar),
`Shift+H` (isolar), `Esc` (cancelar seleção).
**Risco:** baixo. Funções `Editor::picar`, `remover`, `get_mut` já existem.

### E.3 — Gizmo interativo (drag aplica delta)
**O que:** ao clicar perto de uma alça do gizmo (raio vs AABB das alças),
entrar em "modo drag". Capturar ponto inicial no plano y=centro do objeto. A
cada `CursorMoved` enquanto drag, reprojetar o pixel novo no mesmo plano,
calcular delta em metros nos eixos do mundo (ou do objeto, se for modo local),
e aplicar no `Objeto.placement` (via `Editor::get_mut`). Modo
W=mover/E=girar/R=escalar, tecla `Espaço` alterna global/local, `Esc` cancela.
**Risco:** médio. Picking das alças precisa de AABB apertado por alça
(separar `construir_alcas` de `construir_caixa_selecao` no `gizmo.rs`).

### E.4 — Save/Load `.arcz` + Undo/Redo
**O que:** formato `.arcz` = JSON com header (versão, centro, lado) + lista
de objetos (cada um com `fonte` em bytes glTF embutidos ou caminho relativo,
`placement`, `nome`). Persistência em `projetos/<nome>.arcz` por padrão. Cada
operação de transformação vira um `Comando` (struct com `apply`/`revert`),
empilhado em `Historico`. `Ctrl+Z`/`Ctrl+Shift+Z` chamam pop/push. Botão
discreto no header: "salvar" (Ctrl+S).
**Teste de aceite:** a "primeira entrega" do prompt mestre (item 30): abrir
projeto → mexer → fechar → reabrir → transformações preservadas. Snapshots
manuais (E.6) reusam esse mesmo `Historico`.
**Risco:** médio. Implementação cuidadosa dos `Comando` (não acumular estado
pós-revert).

### E.5 — Outliner + Inspector (UI egui)
**O que:** adicionar `egui = "0.32"` e `egui-wgpu`/`egui-winit` ao
`Cargo.toml`. No `viewport.rs::resumed`, criar `egui_ctx` e plugar no loop.
Painel esquerdo: lista clicável dos objetos (Outliner). Painel direito: campos
para o selecionado (transformação, dimensões, nome, visibilidade). Layout
salvo em `~/.config/arcz/ui.json`. **Sem botões decorativos** — só o que tem
ação real por trás.
**Risco:** médio-alto. egui dentro de winit+wgpu exige malabarismo de
`egui-wgpu`. Testar primeiro com um único `Window` e crescer.

### E.6 — Snapshots
**O que:** copia serializada do `Editor` para `projetos/<nome>/snapshots/<ts>.arcz.snap`.
Lista no Inspector (aba "Histórico"). Botão "restaurar" carrega o snapshot de
volta no `Editor`. Snapshots automáticos a cada N minutos (configurável, default 5).
**Risco:** baixo. Reusa o `salvar/carregar` da E.4.
